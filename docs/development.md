## Building

Needs JDK 17 and the Android SDK with API 35 (in `ANDROID_HOME` or in `sdk.dir` of `local.properties`):

```powershell
.\gradlew.bat testReleaseUnitTest assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

`assembleDebug` builds the preview `dev.clawdboard.preview`, which installs next to the real app without touching its data and
accepts the sample data below. `assembleRelease` builds the regular app; locally it goes to `dist\`.

On my machine I use the shortcuts in `scripts\`, which point to Gradle in `D:\Android\gradle-home` and to the JDK installed by
Visual Studio:

```powershell
.\scripts\compilar.ps1
.\scripts\instalar.ps1 -Ip 192.168.0.15   # phone IP with ADB over Wi-Fi; without -Ip it uses the test phone
```

Windows app (Compose Desktop, sharing the core and the raccoon with the phone):

```powershell
.\gradlew.bat :desktop:run                                   # opens the widget
.\gradlew.bat :desktop:packageMsi                            # installer in desktop\build\compose\binaries\main\msi
.\gradlew.bat :desktop:shots --args="prints\<version>\en en" # renders the widget and dashboard screenshots
```

The same `desktop/` module builds the Mac app. On a Mac with JDK 17:

```sh
./gradlew :desktop:run             # opens the menu bar app
./gradlew :desktop:packageDmg      # app in desktop/build/compose/binaries/main/app, DMG next to it
```

The DMG from `packageDmg` needs Finder to draw the Applications shortcut, which fails over SSH. For releases I build it with
`hdiutil` from the `.app`, with a link to `/Applications` next to it:

```sh
mkdir dmg && cp -R desktop/build/compose/binaries/main/app/Banditboard.app dmg/ && ln -s /Applications dmg/Applications
hdiutil create -volname Banditboard -srcfolder dmg -ov -format UDZO Banditboard-<version>.dmg
```

Android alerts with the app closed need `app/google-services.json` from the Firebase project. The file is not in git; without
it the build skips Firebase and the rest of the app works the same.

### iPhone and Apple Watch

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `ios/project.yml`:

```sh
cd ios
xcodegen generate
xcodebuild -project Banditboard.xcodeproj -scheme Banditboard -destination "id=<iPhone UDID>" DEVELOPMENT_TEAM=<team> -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
xcodebuild -project Banditboard.xcodeproj -scheme Banditboard -configuration Release -destination generic/platform=iOS BUNDLE_BASE=dev.clawdboard.banditboard.sideload CODE_SIGNING_ALLOWED=NO build   # the unsigned IPA of the releases
```

`BUNDLE_BASE` sets the bundle IDs of the app, the widget, the watch app and the watch complications. The shared Keychain group
is `<team>.dev.clawdboard.banditboard.shared`, and the app finds the team at runtime, so the same code works when AltStore or
Sideloadly re-sign it with someone else's Apple ID. To build the IPA, copy `Banditboard.app` from
`build/Build/Products/Release-iphoneos` into a `Payload` folder and zip it.

Launch arguments for screenshots in the simulator: `--demo` (sample data), `--lang=pt` or `--lang=en`, `--settings` (opens the
settings), `--scroll-end` (scrolls to the news) and, on the watch, `--page=0`, `--page=1` or `--page=2`.

### Server

`worker/` is the Cloudflare Worker behind "connect from anywhere", with a D1 database:

```sh
cd worker
npx wrangler d1 execute banditboard --remote --file schema.sql
npx wrangler secret put FCM_SERVICE_ACCOUNT    # the Firebase service account JSON, for the Android alerts
npx wrangler deploy
```

It also serves the installers `/pc/box.ps1` and `/pc/box.sh` used by the commands from /conectar.

## Diagnostics over ADB

```powershell
adb shell am start -n dev.clawdboard.preview/dev.clawdboard.MainActivity --ez demo true --es lang EN --es mode MASCOTS --es orient PORTRAIT
# demo: sample data, only works before a PIN is created; mode, orient and backdrop are optional
# also: --ei zoom 150, --es skin XMAS, --es tint RAINBOW, --ei p5 0 (empty session, asleep), --ei p7 97 (red), --ei pf 100 (Fable's own limit), --ez nudge true (feedback card)
# --ez music true turns on the music screen with a sample track playing (raccoons dancing); --ez playing false leaves it paused
adb shell am start -n dev.clawdboard/.MainActivity --ez selftest true  # tests the vault on the device
adb logcat -s ClawdSelfTest
```

## Why Kotlin

The phone app and the Windows app are the same Kotlin code. Jetpack Compose draws the Android screens and Compose
Multiplatform draws the Windows widget, so Racco, his animations, the alert rules, the usage parsing and the texts in both
languages live in one place: change the raccoon once and both apps get it.

The iPhone and Apple Watch apps are SwiftUI, because Apple's widgets and watch complications only exist there. They follow the
same rules as the Kotlin code: the same Racco sprite, the same alert levels and the same texts.

## Architecture

- `core/`: pairing and push, vault, history, settings, music (Android media session) and the web dashboard server
- `ui/`: Jetpack Compose screens and the pixel-art raccoon
- `MediaListener.kt`: the notification listener Android requires to see the active player
- `assets/panel.html`: the web dashboard, with no external dependencies
- `assets/pc/`: the installers and the usage hooks for Windows (PowerShell) and macOS (sh), served by the phone, the desktop app and the server
- `desktop/`: the Windows widget and tray and the Mac menu bar app, with the local server and the home network sharing, built from the same `core/` and `ui/` sources
- `ios/`: the iPhone app, its widgets, the Apple Watch app and the complications, in SwiftUI (`Shared/` is the code they have in common)
- `worker/`: the server behind "connect from anywhere" and the Firebase alerts
- `site/`: the website at banditboard.pages.dev, a static page published by Cloudflare Pages on every push to `main`, with the /conectar page

Some internal names still say `clawdboard` (the `dev.clawdboard` package, `clawdboard-usage.ps1`, the `X-Clawdboard` header).
They stay that way on purpose so existing installs and pairings keep working.
